# Coding Rules and Best Practices

## Core Development Principles

### 1. Communication First
- **Explain what you'll do first** and ask for confirmation before coding
- Describe the approach, files to be modified, and expected outcome
- Wait for explicit approval before proceeding with implementation

### 2. Simplicity First
- **Do the simple thing first** - start with minimal viable solutions
- Avoid over-engineering or adding unnecessary complexity
- Implement the most straightforward approach that meets requirements

### 3. Modular Architecture
- **Use modules instead of single files** for better organization
- Separate concerns into logical modules and packages
- Maintain clean file structure and imports

### 4. Scope Discipline
- **Only make requested changes** - don't add unrequested features
- Stay focused on the specific task at hand
- Avoid scope creep or "helpful" additions not asked for

### 5. Code Reuse
- **Do not write duplicate code** - check existing codebase first
- Look for existing solutions, functions, or patterns to reuse
- Refactor common functionality into shared modules when appropriate

### 6. Documentation Organization
- **Always write markdown documentation in `docs/` path**
- Keep all project documentation organized in the docs directory
- Use clear, descriptive filenames for documentation files

## Implementation Guidelines

- Check existing code before creating new functionality
- Keep functions and classes focused on single responsibilities
- Use clear, descriptive names for variables, functions, and modules
- Follow existing code style and patterns in the project
- Write minimal, focused implementations that solve the specific problem

## Before Every Coding Task

1. ✅ Understand the exact requirement
2. ✅ Check existing codebase for similar functionality
3. ✅ Explain the planned approach
4. ✅ Get confirmation before coding
5. ✅ Implement the simplest solution that works
